# Health V3 — Fresh Run Guide

> **What this is:** A complete end-to-end walkthrough of producing one monthly Health V3 scorecard — from pulling live data through a finished HTML dashboard. Written for someone running this for the first time or after a gap.

---

## The mental model

There are exactly **three outputs** you produce each run:

| Output | File | Who reads it |
|--------|------|-------------|
| Canonical scorecard | `runs/{date}/client_health_scores_{date}.csv` | Source of truth. Archive only. |
| Formatted scorecard | `runs/{date}/client_health_scores_{date}_formatted.csv` | Stakeholder-friendly column subset and order. CSV you send to stakeholders / CEO. |
| HTML dashboard | `dashboards/health_dashboard_{date}.html` | CS team and executives |

The operator (`health_operator_v3.py`) produces the first two automatically in one command. The HTML dashboard is generated separately by an agent using a build prompt.

## Step 1 — Populate the cache (MCP queries)

The operator runs in **cache mode only**. It cannot pull live data itself. You must pre-populate the 10 cache files by running SQL queries against Postgres and BigQuery via MCP tools before running the operator.

**Who does this:** An agent with Postgres and BigQuery MCP access (requires VPN).

**What to run:** The full set of cache-population queries is documented in `README.md` §"How to populate the cache". Each query maps to one of the 10 CSV files above.

**Where to save output:** `Health V3/cache/{score-date}/` — one folder per run, named with the score date (e.g. `cache/2026-05-13/`).

**Verification:** Run the sanity checks documented in `README.md` §"How to populate the cache" — exactly 10 files present, all readable by `pandas.read_csv`, and row counts within ±50% of the prior cache (per-file expected ranges are in that section).

> Use `RUN_PROMPT.md` — it contains the exact MCP queries and file-save instructions ready to paste to an agent.

## Step 2 — Run the operator

Once all 10 cache files exist, run the operator from inside the `Health V3/` directory:

```bash
cd "Health V3"

.venv/bin/python3 health_operator_v3.py \
  --mal "../Health V2/inputs/master_account_list_2026-04-14_canonical.csv" \
  --score-date {YYYY-MM-DD} \
  --cache \
  --cache-dir "cache/{YYYY-MM-DD}" \
  --output-dir "runs/{YYYY-MM-DD}"
```

Replace `{YYYY-MM-DD}` with today's score date (e.g. `2026-05-13`). Use the **same date** for `--score-date`, `--cache-dir`, and `--output-dir`.

**Expected output:**
```
Scored 104 orgs, 0 skipped
Canonical CSV: runs/2026-05-13/client_health_scores_2026-05-13.csv (104 rows, 28 columns)
Formatted CSV: runs/2026-05-13/client_health_scores_2026-05-13_formatted.csv (104 rows, 20 columns)
```

**After the run, record the SHA:**
```bash
shasum -a 256 "runs/{date}/client_health_scores_{date}.csv"
```
This is your canonical SHA. Save it — it's your integrity fingerprint. If you re-run with identical inputs, this hash must not change.

## Step 3 — Generate the HTML dashboard

The dashboard is a single self-contained HTML file. It is generated by an agent using the dashboard build prompt (see `DASHBOARD_POLISH_PROMPT.md`).

**Input the agent needs:**
- `runs/{date}/client_health_scores_{date}.csv` — canonical data source
- `METHODOLOGY.md` — for tooltip and methodology section copy

**Output:**
- `dashboards/health_dashboard_{date}.html`

The agent embeds all data inline — the HTML file has zero external dependencies and can be emailed or opened directly.

## Step 4 — Verify before sending

| Check | How |
|-------|-----|
| 104 rows in both CSVs | Count rows in the formatted CSV |
| SHA matches run_metadata.md | `shasum -a 256 canonical_csv` |
| Dashboard opens in browser without errors | Open the HTML, check DevTools console |
| Queue shows only Critical / At Risk / Floor accounts | Count queue rows — should be ~8, not 14+ |
| Narratives are plain English | Read 3–4 drilldowns at random |

## Common mistakes

| Mistake | What happens | Fix |
|---------|-------------|-----|
| Running operator before cache is populated | `FileNotFoundError: Cache mode enabled but cache/{date}/pg_org_config.csv not found` | Populate the 10 cache files first |
| Using different dates for `--score-date` and `--cache-dir` | Operator looks for cache in wrong folder | Use identical date for all three flags |
| Editing the canonical CSV | SHA mismatch on next verification | Never edit it — use the formatted CSV for stakeholder distribution |
| Running in live mode (omitting `--cache`) | Operator tries to connect to Postgres directly, fails without VPN + local DB | Always use `--cache --cache-dir` for canonical runs |
