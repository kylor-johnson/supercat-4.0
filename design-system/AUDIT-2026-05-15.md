## Summary

| Layer | Status | Notes |
|---|---|---|
| Token foundation (`ds/tokens/`) | **A** | 6 color families, 12-step type ramp, 4-px space ladder with documented contract, dark-theme overrides for color + shadow, `prefers-reduced-motion` handler. Comments explain *why*. |
| Primitives (`ds/primitives/`) | **A−** | 7 primitives (button · input · check · switch · field · date · icon). All consume **semantic** tokens (370 calls, 0 legacy). Some state coverage gaps. |
| Sections (`ds/sections/`) | **C** | Most sections inline-style their components; the ones with `.css` consume **almost entirely** the legacy `--k-*` namespace (793 legacy calls vs. 68 semantic). Card / tag are inline-only — no portable form. |
| Master / Manual chrome | **B−** | Defines orphan tokens (`--k-cream`, `--k-green`, `--k-green-l`) duplicating existing semantic concepts, then uses raw hex literals instead of even those tokens. |

| Accessibility | **B−** | 141 aria, 37 roles, but only **10 `:focus-visible` rules** total. No `aria-invalid` styling anywhere. `field.css` has no implemented states. |

**Components reviewed:** 18 sections · 7 primitives · 6 token files · master + manual + tokens shim
**Score:** 78/100 — strong base, but the section layer is the main drag.

## Naming consistency

| Prefix | Stated purpose (per `NAMING.md`) | Actual usage |
|---|---|---|
| `.kb` (kit button) | buttons | **6 CSS files** + extensive JSX use — alive and consistent |
| `.kf-*` (kit form) | input/check/switch/field/date | **7 CSS files** — alive and consistent |
| `.ki` (kit icon) | icon wrapper | **1 CSS file** + `icon.html` validation — alive |
| `.kc-*` (card) | parked v1 had `.kc-card` | **0 files** — retired (sections use `.ds-card`, **inline-only**) |
| `.ko-*` (modal/overlay) | parked v1 had `.ko-modal` | **0 files** — retired (`.ds-modal-*` lives inside `12-overlays.css`) |
| `.kt-*` (tag) | parked v1 had `.kt-tag` | **0 CSS files** — replaced by `.ds-tag` / `.ds-badge` inside sections |
| `.kdt` (data table) | parked v1 had it | **0 files** — replaced by `.ds-table` / `.ds-tbl-*` |
| `.ds-*` | section-scoped chrome | **11 CSS files** — primary section vocabulary |
| `.kit-*` | legacy body-scope chrome | **1 file** (`tokens.css` back-compat shim) — fine |

**The shape of the regression:** v3c kept the primitives that ARE primitives (button, forms family, icon) but the four primitives that the parked v1 had as importable classes — card, modal, table, tag — **no longer exist as portable primitives**. Their styles live as `.ds-*` selectors inside section CSS files (modal/table/tabs/overlays) or as **pure JSX inline styles** (card, tag) with no CSS file at all. A consumer outside the DS who wants a `.ds-card` has to copy markup + inline styles from `09-cards.jsx` — there's no class to import.

### Sections without a `.css` file (inline styles only)

`00-hero · 01-brand · 03-type · 04-space-grid · 05-iconography · 06-buttons · 07-forms · 08-tags · 09-cards · 10-navigation · 98-footer`

`06-buttons` and `07-forms` are fine to be inline — they're demoing primitives. But `08-tags`, `09-cards`, and `10-navigation` define **the actual visual language** for tag/card/nav-anatomy, and none of it is exportable.

### Sections that have `.css` but live in the legacy `--k-*` namespace

| Section | Semantic calls | Legacy calls | Notes |
|---|---:|---:|---|
| 02-color | 63 | 0 | Plus 148 raw hex — expected; it's the swatch demo |
| 11-tabs | 5 | 81 | Started migration; mostly legacy |
| 12-overlays | 0 | 122 | Modal anatomy entirely in `--k-*` |
| 13-tables | 0 | 133 | Table anatomy entirely in `--k-*` |
| 14-charts | 0 | 69 | Chart palette uses hex literals + `--k-*` |
| 15-patterns | 0 | 60 | All `--k-*` |
| 16-motion | 0 | 66 | All `--k-*` (and legitimately demonstrates `Nms`) |
| 17-code | 0 | 79 | All `--k-*` |

The system has **two parallel token languages coexisting** — the modern semantic set (`--text-*` etc.) which primitives use, and the legacy `--k-*` set which sections use. The README warns "do not use `--k-*` in new code" but sections haven't been migrated.

**Common primitive gaps:**
1. **`:focus-visible` is underrepresented** — 10 rules across the whole DS. Each primitive should have a clear ring. The benchmark button has only 2 `:focus` rules and inherits ring via `--kb-focus-ring`. Verify nothing falls through.
2. **No `aria-invalid` styling on any form primitive** — visually-flagged error state is missing despite `--status-danger` and `--status-danger-tint` being defined.
3. **`field.css` is a 224-line wrapper with 0 states implemented** — hover/focus/active/disabled all 0. Likely intentional (it's a layout wrapper) but the `--error` block (1 rule) suggests the intent is incomplete.
4. **Button** has `error=0` but a `.kb-danger` variant ships in v3c (mentioned in tokens). Verify the destructive button is wired up across all states (hover/active/disabled/focus).

## Accessibility

- **`:focus-visible` rules: 10 total** in 7 primitive files + a handful of sections. Should be at least one per interactive control. Audit each `.ds-modal-close`, `.ds-tabs-comp`, segmented control, sortable table header.
- **`aria-invalid` styling: nonexistent**. `field.css` has a placeholder for error state but no consumer flips it.
- **`prefers-reduced-motion`** is honored in tokens (durations collapse to 0ms) but only 9 files explicitly reference it. The motion-demo section (`16-motion.css`) does NOT (it's *demonstrating* motion, so this is justified).
- **`aria-live` for toast/snackbar patterns**: not surveyed (v3c has no toast primitive).
- **Color contrast**: the dark-theme override for `--text-crimson` (`#B83A3F` on `#131211`) is explicitly engineered for WCAG AA — the token comment says so. But the system has no automated contrast check.

## Priority actions

Effort is rough order-of-magnitude. Impact = how much the system improves overall.

### P0 — Quick wins (≤2h each, high payoff)

1. **Normalize the `#fff` vs `#FFFFFF` casing** and route through `var(--color-white)` system-wide. Trivial sed, but cleans the audit signal and removes the only "raw-hex inside primitive button.css" hit (which is just `color-mix(... #fff)`).
2. **Resolve the `--k-cream` / `--k-green` orphan tokens** (master.css). Either (a) promote them to canonical semantic tokens with proper names (`--text-on-crimson-soft`, `--status-success-deep`), or (b) delete them and migrate the 46 call sites (`#EDE4D6` + `#2D4F2E`) to existing semantics (`--text-on-crimson`, `--status-success`) — accepting the small color shift. The duplicate-and-then-ignore pattern is worst-of-both-worlds.
3. **Align reference.html version chip** (`v0.5` → `v0.4`) with README/PROGRESS.
4. **Add `--chart-*` semantic palette** (8–10 named slots) in `ds/tokens/semantic.css` and migrate `14-charts.css` off raw hex. Charts need their own ramp anyway.
5. **Fix `--k-green`'s drift from `--status-success`** — light theme has `#2D4F2E` vs semantic `#2D6A4F`. Decide which is the actual brand success and unify.

### P1 — Section migration (~half-day each, scales the system)

6. **Promote `.ds-tag` / `.ds-badge` to a portable primitive** (`ds/primitives/tag.css` + `.md`). Pull patterns from `08-tags.jsx`. Variants: accent/support/success/warning/danger/info/neutral. Sizes: sm/md. This is the smallest section-housed component and the most-asked-for in consumers (already shipped at `tariff-refund-26-tlc-v2`).
7. **Promote `.ds-card` to a portable primitive** (`ds/primitives/card.css` + `.md`). Pull `09-cards.jsx` patterns. Slots: head/body/foot. Variants: flat / interactive / feature / inverse. The parked v1 had this — port it carefully, don't revert.
8. **Migrate `12-overlays.css` from `--k-*` → semantic tokens.** 122 legacy calls → equivalent semantic refs. Verify modal looks identical in both themes before/after.
9. **Migrate `13-tables.css` from `--k-*` → semantic tokens.** Same playbook. 133 legacy calls.
10. **Migrate remaining section CSS files** (11-tabs, 14-charts, 15-patterns, 16-motion, 17-code) — straightforward find/replace once the playbook is set, but each needs a visual diff against the old.

### P1 — Primitive coverage (≤1d each)

11. **Wire `aria-invalid` styling across `.kf-input`, `.kf-check`, `.kf-switch`, `.kf-field`** using `--status-danger` and `--status-danger-tint`. Verify in `forms.html`.
12. **Audit every interactive surface for `:focus-visible`** — buttons, links, tabs, modal close, sortable table headers, segmented controls. The DS has `--shadow-focus` ready; it just needs to be applied.
13. **Modal JS controller** (`ds/primitives/modal.js` or fold into a generic dialog controller) — the parked v1 had focus-trap + ESC + click-outside + focus-restore. Without it, every consumer recreates the wheel.

### P2 — Project-scale (>1d, plan deliberately)

14. **Decide and act on the brand/product matrix.** PROGRESS.md notes this. If TLC clay-vs-gold flip is still on the roadmap, design how it layers on top of the new 3-tier base — don't revert. Suggest a discrete `ds/tokens/brand/*.css` opt-in.
15. **`app/tokens.jsx` cleanup** — pre-reset queued item. Refactor `app/screen-*.jsx` to consume `ds/tokens.css` directly, delete the JS-object duplicate.
16. **Re-establish a verification harness** — at least one `verify-*.html` per surface (master, app, content) that iframes the page in light + dark. Pattern from the parked `_legacy/_backup/2026-05-15/docs/verify-nav.html` is reusable.
17. **Centralized icon set** — v3c retired the SVG sprite in favor of per-icon inline paths. Either restore a sprite (small, ~2KB) or ship a JSX icon component family that imports paths from one source. Today every consumer pastes the same `<svg>` markup.

### Out of scope (intentionally not on this list)

- `nav/nav.css` migration — parked by `feedback_premature_migration.md`. Don't touch without a concrete cross-brand consumer.
- Reverting v3c to v1.0.0-rc1 — the user's stated direction is to improve forward, not roll back.
- Build pipeline / `dist/` bundle — v3c removed this on purpose. Reintroduce only if a consumer demands a single-file CSS.
